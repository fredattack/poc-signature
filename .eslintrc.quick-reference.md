# ESLint Quick Reference

Quick guide for common linting tasks and fixes.

## Quick Commands

```bash
# Check for issues
npm run lint

# Auto-fix issues
npm run lint:fix

# Format code
npm run format

# Full quality check
npm run quality

# Full quality check + auto-fix
npm run quality:fix
```

## Common Fixes

### 1. Sort Imports

❌ **Wrong:**
```typescript
import { View, Text, Button } from 'react-native';
```

✅ **Correct:**
```typescript
import { Button, Text, View } from 'react-native';
```

**Fix:** Run `npm run lint:fix`

### 2. Sort StyleSheet Properties

❌ **Wrong:**
```typescript
const styles = StyleSheet.create({
  container: {
    flex: 1,
    backgroundColor: '#fff',
    padding: 20,
  },
});
```

✅ **Correct:**
```typescript
const styles = StyleSheet.create({
  container: {
    backgroundColor: '#fff',
    flex: 1,
    padding: 20,
  },
});
```

**Fix:** Run `npm run lint:fix`

### 3. Handle Promises

❌ **Wrong:**
```typescript
const handlePress = () => {
  fetchData(); // Floating promise
};
```

✅ **Correct:**
```typescript
const handlePress = () => {
  void fetchData(); // Explicitly ignored
  // OR
  fetchData().catch(console.error); // Handled
  // OR
  fetchData().then(() => {}).catch(() => {}); // Fully handled
};
```

**Manual fix required**

### 4. Async Event Handlers

❌ **Wrong:**
```typescript
<Button onPress={async () => await save()} />
```

✅ **Correct:**
```typescript
<Button onPress={() => { void save(); }} />
// OR create a proper handler
const handlePress = () => {
  save().catch(console.error);
};
<Button onPress={handlePress} />
```

**Manual fix required**

### 5. Remove Unused Styles

❌ **Wrong:**
```typescript
const styles = StyleSheet.create({
  container: { flex: 1 },
  unusedStyle: { padding: 10 }, // Never used in JSX
});
```

✅ **Correct:**
```typescript
const styles = StyleSheet.create({
  container: { flex: 1 },
});
```

**Manual fix required**

### 6. Use Theme Colors

❌ **Wrong:**
```typescript
const styles = StyleSheet.create({
  container: {
    backgroundColor: '#fff', // Color literal
  },
});
```

✅ **Correct:**
```typescript
const styles = StyleSheet.create({
  container: {
    backgroundColor: theme.colors.background,
  },
});
```

**Manual fix required**

### 7. Avoid `any` Type

❌ **Wrong:**
```typescript
const data: any = response;
```

✅ **Correct:**
```typescript
const data: ResponseType = response;
// OR
const data: unknown = response;
```

**Manual fix required**

### 8. Unused Variables

❌ **Wrong:**
```typescript
const [data, setData] = useState(null); // setData never used
```

✅ **Correct:**
```typescript
const [data, _setData] = useState(null); // Prefix with _ if intentionally unused
// OR remove it
const [data] = useState(null);
```

**Manual fix required**

### 9. Escape Characters in JSX

❌ **Wrong:**
```tsx
<Text>Don't do this</Text>
```

✅ **Correct:**
```tsx
<Text>Don&apos;t do this</Text>
// OR
<Text>{"Don't do this"}</Text>
```

**Manual fix required**

### 10. Nullish Coalescing

❌ **Warning:**
```typescript
const value = someValue || defaultValue; // Warning for nullable types
```

✅ **Better:**
```typescript
const value = someValue ?? defaultValue;
```

**Fix:** Run `npm run lint:fix` (may auto-fix)

## Disable Rules (Use Sparingly)

### Disable for Next Line
```typescript
// eslint-disable-next-line rule-name
const problematicCode = something;
```

### Disable for Entire File
```typescript
/* eslint-disable rule-name */
// File contents
```

### Disable Multiple Rules
```typescript
/* eslint-disable rule-one, rule-two */
// File contents
```

## Common Rule Names

- `@typescript-eslint/no-explicit-any` - Disallow `any` type
- `@typescript-eslint/no-unused-vars` - No unused variables
- `@typescript-eslint/no-floating-promises` - Handle promises
- `@typescript-eslint/no-misused-promises` - Promise type errors
- `react-native/no-unused-styles` - Remove unused styles
- `react-native/sort-styles` - Sort StyleSheet properties
- `react-native/no-color-literals` - Use theme colors
- `react-native/no-inline-styles` - Use StyleSheet
- `sort-imports` - Sort import members
- `prettier/prettier` - Code formatting

## IDE Setup

### VSCode

1. Install ESLint extension
2. Install Prettier extension
3. Enable format on save in settings:
   ```json
   {
     "editor.formatOnSave": true,
     "editor.codeActionsOnSave": {
       "source.fixAll.eslint": "explicit"
     }
   }
   ```

### PhpStorm/WebStorm

1. Enable ESLint: Settings → Languages & Frameworks → JavaScript → Code Quality Tools → ESLint
2. Enable Prettier: Settings → Languages & Frameworks → JavaScript → Prettier
3. Enable "Run eslint --fix on save"
4. Enable "On save" for Prettier

## Troubleshooting

### Linting is slow
- Check if you're linting `node_modules` (should be in `.eslintignore`)
- Try `npm run lint -- --cache` to use ESLint cache

### Auto-fix doesn't work
- Some rules can't be auto-fixed (marked as "Manual fix required" above)
- Check for syntax errors first
- Try running `npm run format` separately

### Pre-commit hook fails
1. Run `npm run quality:fix`
2. Fix remaining manual errors
3. `git add .`
4. Retry commit

### Rules conflict
- ESLint and Prettier are configured to work together
- If you see conflicts, report it as it shouldn't happen
